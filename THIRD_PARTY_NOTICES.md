# Third-party notices

PHISIKS itself is MIT-licensed (`LICENSE`). It builds against the following third-party libraries. They are placed in `vendor/` (not committed: `python tools/fetch_deps.py` downloads the portable ones at pinned versions; the Windows PhysX and GLFW binaries are placed by hand, see `BUILD_WINDOWS.md`). They are used unmodified, apart from the ImGuizmo compatibility patch below, and remain under their own licences.

**Licence texts.** `tools/fetch_deps.py` collects each library's licence text, at the pinned version, into `vendor/licenses/`. Release packages ship them in `THIRD_PARTY_LICENSES/`. If you redistribute binaries built another way, include those texts as well.

**Open CASCADE (LGPL-2.1 + exception).** OCCT is linked dynamically and only by `PhisiksCad`, a shared library, so no OCCT code is compiled into PHISIKS's own binaries. Release packages and the SDK ship the unmodified OCCT shared libraries (`TK*.dll` / `libTK*.so` / `libTK*.dylib`) next to `PhisiksCad`, with `LICENSE_LGPL_21.txt` and `OCCT_LGPL_EXCEPTION.txt` in `THIRD_PARTY_LICENSES/OpenCASCADE/`. Under the LGPL you may replace those libraries with your own build of the same OCCT version (ABI-compatible): `tools/build_occt.py` shows the exact source (tag `V7_9_3`, SHA-256 checked) and options. The OCCT source is available from the upstream links above. If you redistribute PHISIKS, keep the libraries replaceable and include those licence texts. Built with `-DPHISIKS_CAD_KERNEL=None`, PHISIKS contains no OCCT at all (CAD sketches and documents still work, solids do not).

PhysX is optional: it is the Windows default, and the native backend replaces it elsewhere and in the CI-built archives. The FSR 1.0-style upscaler is an original implementation of the published algorithm (no AMD code). PHISIKS does not ship or link any other third-party code.

The assets in `assets/` are generated by `tools/assetgen` (original, CC0).
